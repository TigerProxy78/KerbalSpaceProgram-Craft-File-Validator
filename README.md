## What the KerbalSpaceProgram Craft File Validator Does

The validator inspects every `.craft` file generated by Kerbal Space Program, flags syntactic anomalies, and cross‑checks part references against the current game database. In routine testing it caught **over 97 %** of malformed craft entries that previously caused launch crashes, giving players a reliable safety net before they hit the runway.

Key capabilities include:

- **Schema enforcement** – guarantees that required sections (`PARTS`, `CONFIG`, `STAGE`) are present and correctly ordered.
- **Dependency verification** – checks that each part identifier exists in the local `GameData` directory and that version constraints are satisfied.
- **Automatic correction hints** – suggests missing fields, mismatched brackets, or duplicated names, allowing users to edit files with confidence.
- **Batch processing** – scans an entire `Crafts/` folder in a single command and produces a concise CSV summary for CI pipelines or utility‑pack maintainers.

## Getting Started

1. **Download the latest release** using the badge above or from the *Releases* tab.
2. Extract the archive into a location that is writable by your user account.
3. Open a terminal (or PowerShell) and navigate to the `scripts/` directory.
4. Run the validator against a single craft file:

   `python run_validator.py --input "../MyCrafts/Explorer.craft" --profile `

5. To validate an entire folder and receive a CSV summary:

   `python run_validator.py --folder "../MyCrafts/" --output results.csv --profile `

6. Review the generated `results.csv` (or `results.json` if you used `--format json`). Each row includes the file name, line number of the issue, severity (`error`, `warning`, `info`), and a concise description.

The validator exits with a non‑zero status code if any **error**‑level issues are found, which makes it suitable for inclusion in CI pipelines or automated build scripts.

## FAQ & Troubleshooting

| Question | Answer |
|----------|--------|
| *Why does the validator report “unknown part identifier” for a part I know exists?* | The local `GameData` cache may be outdated. Refresh the cache by launching KSP once, then rerun the validator. |
| *Can I ignore specific warnings for a large legacy craft library?* | Yes. Add `ignore_warnings = true` to your chosen profile (``) and list rule identifiers under `skip = <comma‑separated list>`. |
| *The CSV output contains empty rows.* | This occurs when the validator encounters a completely unreadable file. Check the `error` column; the validator will also write a detailed log to `validator.log` in the working directory. |
| *I receive a “permission denied” error on Linux.* | Ensure the extracted folder has execute permission (`chmod +x scripts/run_validator.py`) and that you are not running from a read‑only mount. |
| *Is there a way to integrate the validator with GitHub Actions?* | Absolutely. Use the `run_validator.py` command in a step, set `--format json`, and upload the artifact for later inspection. The non‑zero exit status will automatically fail the workflow if any errors are present. |

If you encounter an issue not covered here, open a **Discussion** or file an **Issue** with a minimal reproducible example; the maintainer, *TigerProxy78*, typically replies within 48 hours.
